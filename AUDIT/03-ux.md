# Phase 3 — Client experience

Walked as **owner** and as an actual **client** (portal), at desktop and phone widths, in French, English and Arabic. Contrast, focus and layout numbers below were measured in the running app, not estimated.

## Fixed in this phase

### U1 — The pinned actions column was transparent, so its icons sat on top of the data
**Location** `app/flow.css`, `app/globals.css`

`.task-table .actions-cell` is `position: sticky; right: 0` — it pins the edit/delete icons to the edge while the table scrolls. But a glassmorphism rule, repeated with `!important` in **four** stylesheets, sets

```css
.task-table, .task-table tr, .task-table th, .task-table td, .table-area { background: transparent !important; }
```

which beat the cell's own `background:#fff`. The pinned column was see-through, so on any narrow window its icons were drawn over the client name. Measured: `background-color: rgba(0, 0, 0, 0)` on a sticky cell.

**Fix applied** An opaque background at higher specificity (`.task-table td.actions-cell`), so it wins regardless of which stylesheet loads last. Verified at 375 px: icons now sit on a clean surface.

### U2 — A month calendar showed three days of seven on a phone
**Location** `app/flow.css`

`.calendar-days { grid-template-columns: repeat(7, minmax(105px, 1fr)); min-width: 735px }` inside a 349 px container. The grid *was* horizontally scrollable, but with no affordance — a client opening their calendar on a phone saw Monday to Wednesday and nothing suggesting the rest of the week existed.

**Fix applied** Under 768 px the seven columns fit the width, with shorter day cells and the event's secondary line hidden. Verified: the full week renders on a 375 px screen.

### U3 — Form labels and select placeholders failed AA contrast
**Location** `app/modern.css` → corrected in `app/flow.css`

`.form-field > span` was `#808ca0` at 13 px → **3.14:1** (AA wants 4.5:1). This is *every* form label in the app. Select placeholders (`.pick`) were **2.8:1**, the sidebar caption **2.14:1**, the search placeholder **2.9:1**, the "Privé" indicator **3.55:1**, client card counts **3.96:1**.

**Fix applied** All raised past 4.5:1. Two of them — the ⌘K hint and the nav counter — sit on the **dark** sidebar, where the first attempt made them worse; they were corrected in the other direction (lighter) and verified at 7:1+. The clients page now measures **0 contrast failures**.

## The finding that needs Phase 5: contrast is a token problem, not a list of bugs

After fixing the reachable cases, a sweep of seven pages still returned **45 failures**, and they collapse into one cause: the app has a single muted-text tone, somewhere in `#8b96a7`–`#afb5c0`, applied to secondary text everywhere, and it does not reach AA on these light surfaces.

| Element | Ratio | Needs |
|---|---|---|
| Unclassed `<p>` help text (`Les accès sont vérifiés…`) — 14 instances | **2.57** | 4.5 |
| Section eyebrows (`MEMBRES`, `GESTION DES ACCÈS`…) — 7 | **2.66** | 4.5 |
| `.team-tip p` | **1.90** | 4.5 |
| Avatar initials (white on amber) | **1.08** | 4.5 |
| `.row-count` ("3 tâches") | **2.39** | 4.5 |
| `.file-pill` ("Ouvrir") | **2.77** | 4.5 |
| `.status.s3` ("Validé") | **3.82** | 4.5 |
| `.flow-target` ("Cible ≥ 95 %", on dark) | **4.38** | 4.5 |

I tried to fix these from `app/flow.css` and **seven of the rules never landed** — later stylesheets (`print.css`, `team.css`, `invoice.css`) override them with `!important` or higher specificity. Rather than escalate an `!important` war, I removed the rules that did not apply and left the problem for Phase 5, where a single authoritative token layer loaded last is the right instrument. This is logged there as the primary driver for consolidating the stylesheets.

## Verified good

- **Every form control has an accessible name.** A sweep for inputs/buttons/selects with no label, `aria-label`, wrapping label or title returned **zero**.
- **Keyboard focus is visible**: a real Tab press produces a 2 px amber outline (`:focus-visible`). Inputs use a border-colour change plus a `:focus-within` ring on the search field — weaker, but present.
- **Landmarks and headings**: one `<h1>` per page, a `<main>` landmark, `lang` and `dir` mirrored onto `<html>` on every locale change.
- **RTL (Arabic) is properly implemented**, not merely translated: the sidebar moves to the right, the sticky actions column pins to the *left*, text aligns right, and there is **no horizontal overflow**. Arabic is now 100 % translated (Phase 1).
- **Mobile**: no horizontal page overflow at 375 px on the portal or the studio; the sidebar collapses; forms stack; the tasks table gets a real scrollbar.
- **No N+1 queries in the hot path**: `payload()` runs its three queries in parallel, `loadRecords` is one query plus one roster query.
- **The API is fast at current scale**: `GET /api/records` → 20 ms, 20 KB for 43 records.

## Not fixed — logged for decision

### P1 (performance, the one that will bite) — the entire workspace ships on every 5-second poll
`GET /api/records` returns every record the role may see; the client polls it every 5 seconds per open tab. `trimForTransport` already caps events at 90 days and task history at 30 entries — but **tasks, comments, editorial posts and documents are unbounded**.

Today: 43 records, 20 KB. A studio two years in (≈700 tasks with comments, plus events) lands in the 1–2 MB range **per poll, per tab**. Nothing in the code degrades gracefully: there is no pagination, no cursor, no `If-Modified-Since`, and no virtualised list — every row is rendered.

Options, cheapest first: (a) send a hash and skip the body when nothing changed; (b) cap tasks/comments the way events are already capped; (c) paginate the tables. Needs your call because (b) changes what the UI can show.

### P2 — 42 of 61 `components/ui/*` files are never imported
`accordion, alert, aspect-ratio, attachment, avatar, badge, breadcrumb, bubble, button-group, calendar, card, carousel, chart, checkbox, collapsible, combobox, command, context-menu, direction, drawer, dropdown-menu, field, form, hover-card, input-otp, item, kbd, marker, menubar, message, message-scroller, native-select, navigation-menu, pagination, radio-group, resizable, scroll-area, slider, sonner, spinner` and more.

Ten dependencies exist **solely** to serve those unused files: `embla-carousel-react`, `cmdk`, `input-otp`, `vaul`, `react-day-picker`, `sonner`, `react-resizable-panels`, `react-hook-form`, `@shadcn/react`, `next-themes`. Two more — `@hookform/resolvers` and `date-fns` — are imported by **nothing at all**.

Unimported files should not reach the bundle, so this is mostly install/maintenance weight rather than shipped bytes — but the built output is still **2.1 MB of JS with a single 1.3 MB chunk**, and the surviving `chart.tsx` → recharts path *is* reachable (used by the print dashboard). Deleting files and dependencies is a removal, so I have not done it: **your call**.

### P3 — two "Download" buttons, two different behaviours
Studio quotes/invoices produce a real PDF via `pdf-lib`; the print workspace's invoices open a hidden iframe and call `print()`. `lib/document-pdf.ts` is imported by the print workspace and never called. Same word, same icon, different outcome.

### P4 — smaller friction, no change made
- The tasks table is 1 295 px wide; at 694 px, Assignee → Time are reachable only by horizontal scroll, with no visual hint on desktop (mobile does get a scrollbar).
- A session that expires while a modal is open discards the unsent form content (Phase 2, U1).
- A background poll that receives 401 does nothing, so the screen keeps showing stale data until the next click (Phase 2, U2).
- No skip-to-content link.
- Input focus is a 1 px border change against the button's 2 px outline — inconsistent weight.
