# Full audit — design system, features, dead code, performance

**Audited** 26 September 2026, on the app as deployed (commit `9ab2e79`), against a local copy seeded with
realistic data: 3 clients, 15 tasks in every status, quotes and invoices, social posts, a creative, a social
media manager, a client contact, and a print workspace with an order, a payment and a task.

**Method, in short** — nothing below is from reading code alone:

| Check | How |
|---|---|
| Visual baseline | 87 screenshots: every page and tab, for the owner, a member, a client and the print workspace, at desktop (1440 px) and phone (390 px) width |
| Every button works | A crawler reloaded each page and clicked every button, tab and link one at a time — **430 controls on 38 page visits**, 4 roles — logging JavaScript errors, failed requests and controls that do nothing |
| Real journeys | 7 end-to-end flows through the UI: create a task, comment, save a draft post, invite a member, client approves a deliverable, client requests content, record a print expense |
| Design consistency | The rendered style (colour, border, corner radius, height, font) of every button, field, badge, card and page title on every page, grouped into variants |
| Dead code | `knip` for unused files, exports and dependencies, each hit confirmed by search; a script for CSS classes no code uses |
| CSS changes are safe | Pixel comparison of all 87 screenshots before and after, on identical data |
| Performance | Production builds of the old and new code, measuring what the sign-in page downloads |

## 1. Features — what the crawl and the journeys found

**No JavaScript error and no failed request** on any of the 430 controls, for any role. All 7 journeys pass.

**Bugs found and fixed**

| # | Bug | Fix |
|---|---|---|
| F1 | **The "Refresh" button in the studio's top bar could not be clicked** — the floating notification bell sat on top of it (the crawler's click was intercepted by `.notification-bell` on every studio page). | The top bar keeps room for the bell at its end (RTL-aware). |
| F2 | **The print workspace's Team page showed two headings stacked** — the print header ("Your workshop at a glance · Team") and the shared Team page's own. | Team and Activity keep only their own heading. |
| F3 | **French words in English and Arabic**: the print menu's « Factures », the phone bar's « Plus », and in the client portal the document type and status (« Facture », « Brouillon »). | Translated (en + ar); the portal now passes both through translation. |
| F4 | **« Copier le texte » in the Library silently did nothing** where the browser refuses clipboard access. | Falls back to a selected text field; "Copied" only shows when it really copied. |

**Checked and working as intended** (reported by the crawl as "no visible effect", each verified by hand): *Today* on a calendar already on today; *Refresh* with unchanged data; forms submitted empty (stopped by the browser's required-field check); *Add a logo / banner* (opens the file picker); *Print / PDF* (opens the print dialog); an Activity row for someone with no activity. **Downloads verified separately**: a client's invoice PDF and the print CSV export both download.

## 2. Design system — measured, then aligned

The previous audit created `app/tokens.css` but left six diverged copies of the same override layer
fighting each other (C1). This pass measured what actually renders, then brought each component to one
definition.

**Measured drift, now fixed**

| Component | Before | After |
|---|---|---|
| Primary button | corner radius **10 px** (three `!important` rules), every other button 8 px | 8 px, like all buttons |
| Button text | **11, 12 and 13 px** at the same 38 px height, depending on the page | **two sizes**: default 38 px / 13 px; compact 32 px / 12 px for buttons inside cards, deliverables and side panels |
| Text fields | **36, 37 and 46 px** high, 12–14 px text | 38 px / 13 px everywhere (search boxes 13 px too) |
| Status badges | 11 px/500 in some places, 12 px/600 in others, 22–25 px high | one badge: 11 px / 600, 22 px |
| Page titles | studio 30 px, print 29 px | 30 px |
| Typeface | the invoice screens asked for **"Plus Jakarta Sans", a font never loaded** (so they fell back to a generic sans-serif); Inter and Archivo were downloaded from Google on every page for 2 elements | **one typeface**, the system's (`--t-font`: SF Pro / Segoe UI / Roboto) — no font download at all |
| Portal account cards | the only flat, 12 px-corner cards | the app's card radius and elevation |
| Colours | 108 hard-coded copies of the brand amber, its hover/border/ink and the hairline | now the tokens (`var(--t-brand)`, `var(--t-line)`…) — a rebrand changes one line |
| Breakpoints | 760, 767 and 768 px; 980, 999 and 1000 px | 767 px and 1 000 px |

All standards live in one block at the end of `app/tokens.css` ("Component standards"), with the new
control-height tokens `--t-control-h` / `--t-control-h-compact`.

**Stylesheet cleanup, proven invisible.** A cascade-aware pass (PostCSS) removed:
- **1 133 declarations** that could never apply — a later rule with the *exact same selector*, in the same `@media`, sets the same property with equal or higher importance (repeats inside one rule, i.e. browser fallbacks, were kept);
- **201 selectors** for 55 classes no code uses (`google-btn`, `auth-tabs`, `demo-caption`, `member-row`, `zoom-tools`…);
- **460 rules** left empty.

Screenshots of the original CSS and of this pass alone, on the same data: **80 of 87 pixel-identical**; the other 7 differ only where the data moved between runs (a test user's first sign-in changed "Pending", "last sign-in" and the Activity timers).

## 3. Dead code removed

- **46 unused UI components** (`components/ui/`: accordion, carousel, calendar, command, drawer, form, input-otp, sonner, toggle… — 15 remain, all in use).
- **13 unused dependencies**: `@base-ui/react`, `@hookform/resolvers`, `@shadcn/react`, `cmdk`, `date-fns`, `embla-carousel-react`, `input-otp`, `next-themes`, `react-day-picker`, `react-hook-form`, `react-resizable-panels`, `sonner`, `vaul` (decision D2 of the last audit).
- **2 dead scripts**: `scripts/check-google-config.mjs` (`pnpm auth:check`, checked Google sign-in variables the app no longer reads — D3) and `scripts/seed-internal.ts` (created a fake "internal" client the app no longer uses).
- **6 dead functions/constants** referenced nowhere: `localeForLanguage`, `metaPublishingConfigured`, `sources`, `accountStates`, `normalizeWhatsapp`, `socialAccess` (replaced by `accountsAccess` when clients got their own account connections).
- The Google Fonts `<link>`s in `app/layout.tsx`.

## 4. Performance

| Change | Effect |
|---|---|
| **Screens load on demand** (`next/dynamic`): client portal, print workspace, Social hub, dashboard, activity, library, contract annex, time records, and the home page's charts | The sign-in page and the studio home no longer download them; JS on sign-in **2 159 → 1 102 KB** |
| **PDF generation loads on click** (`pdf-lib`, ~410 KB) | Only when someone downloads an invoice or an invitation PDF |
| **Background poll answers 304** when nothing changed (`ETag` on `GET /api/records`, `If-None-Match` from the page) | Every 5 s per open tab, the unchanged workspace is no longer re-sent nor re-rendered — the payload-growth risk P1 is contained for idle tabs. New test in `tests/records.mjs`. |
| **No Google Fonts** | One less render-blocking, third-party request on every page |
| CSS −36 % | Less to download and to match |

Measured on production builds served locally (sign-in page, cold cache). A signed-in studio page could
not be measured in production mode locally (it needs the real database), but it benefits from the same split.

## Still open — recommendations

| # | What | Why |
|---|---|---|
| R1 | **Finish collapsing the override layer** (C1). 577 `!important` remain, mostly the glassmorphism pass still spread over `globals`, `modern`, `flow`, `team`, `login` and `print`. The safe part is done; the rest means rewriting rules whose effects differ, one component at a time, each checked by screenshot. | Every new style still has to fight the cascade. |
| R2 | **Tables on phones**: the print "Income & expenses" table, the documents table and the team table still scroll sideways on a phone; the tasks table already reads as cards. | Same card treatment, 1–2 hours each. |
| R3 | **Server-side payload** (P1): the 304 spares the download, but the server still loads the whole workspace every poll. | Pagination or an "updated since" query once the data grows. |
| R4 | **Error reporting** (M7) — still `console.error` only. | First news of a production failure is a human. |
| R5 | **Password reset by e-mail** (M6). | The owner account is the only one that can create clients. |
