# WhatsApp approval and assignment notifications — 1 October 2026

## Changes

- Approval requests no longer silently skip clients when WhatsApp credentials or the approval template are missing. The saved task remains intact; the app and Activity report the missing setting or Meta error.
- Meta responses must contain a message ID before being reported as accepted. Acceptance is not a delivery receipt.
- Explicit template language settings avoid unnecessary discovery requests. Automatic discovery remains available, with a bounded timeout and a cache scoped to the sending number and template.
- Managers can resend an approval notification from a waiting task. An atomic database lease limits retries to one per task every 60 seconds, including concurrent requests.
- Team invitations and member profiles now support normalized international WhatsApp numbers. Contacts belong to the workspace and are private to its managers and the member. They are removed when membership is revoked.
- Assignment notifications use an independent four-variable approved template. They cover regular tasks, accepted portal requests, content-plan assignments and print tasks. Self-assignment, removing an assignment, unrelated edits and rejected concurrent writes do not send.
- Assignment failures are visible and never undo task saves. All provider calls are awaited within the route timeout; credentials never enter browser payloads.
- Disabled buttons use the shared surface and text tokens in both themes; removed the old hardcoded light gray disabled primary background.

- Assignment: approve `tache_assignee` with four positional body variables (member, task, assigner, sign-in URL), then configure `WHATSAPP_ASSIGNMENT_TEMPLATE` and its exact language in Vercel and redeploy. See README → WhatsApp for the template.
